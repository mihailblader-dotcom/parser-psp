# avito-watcher (Go)

Следит за выдачей Авито и присылает новые объявления в супергруппу Telegram с темами: каждый раздел конфига (PSP, PS Vita, Nintendo 3DS…) уходит в свою тему.

## Сборка

Нужен Go 1.22 или новее.

```bash
go mod tidy                      # скачает goquery
go build -o avito-watcher .

# собрать под Linux-сервер на Windows/Mac:
GOOS=linux GOARCH=amd64 go build -o avito-watcher .
```

Получается один исполняемый файл без зависимостей: Python, venv и lxml на сервере не нужны.

## Настройка Telegram

1. Создайте группу и в её настройках включите **Темы** (группа станет супергруппой с разделами).
2. Добавьте бота и сделайте администратором с правами «Отправка сообщений», «Удаление сообщений» и **«Управление темами»**.
3. Узнайте `chat_id` группы (вида `-100…`): напишите в группе `/start@имя_бота`, откройте `https://api.telegram.org/bot<токен>/getUpdates` и найдите `"chat":{"id":-100…}`.
4. Темы. При `"auto_create_topics": true` бот сам создаст тему с именем раздела при первом запуске и запомнит её номер в `state.json`. Если тема уже есть, впишите в раздел `"topic_id"` — это число из ссылки на любое сообщение в теме: `https://t.me/c/<чат>/<topic_id>/<сообщение>`.

Если тему удалить, бот заметит это при следующей отправке и создаст её заново (для тем из `topic_id` в конфиге — напишет в лог и будет слать в общий поток).

## Запуск

```bash
cp config.example.json config.json   # впишите токен и chat_id
./avito-watcher -once -debug          # один проход по всем разделам, причины отсева в логе
./avito-watcher                       # обычная работа
```

Первый проход по каждой ссылке молчаливый: всё, что сейчас в выдаче, запоминается без отправки, иначе в чат вывалилась бы вся первая страница. Добавленная позже ссылка тоже проходит первый раз молча.

После первого запуска проверьте лог: не должно быть строки «ни у одного объявления не определилось время публикации». Если она есть — Авито поменял вёрстку; `-debug` сохранит страницу в `debug_last_page.html`.

## Фильтры

Слова в `title_include`, `title_exclude`, `description_exclude` ищутся **с начала слова**, без учёта регистра, ё = е:

- `плата` найдёт «плата», «платы», но не «оплата» и не «предоплата»;
- `зарядк` найдёт «зарядка», «зарядкой»;
- `300 игр` не сработает на «1300 игр».

Запись `re:выражение` — регулярное выражение (синтаксис RE2). Учтите, что `\b` в Go понимает только латиницу; для кириллицы используйте `(^|[^\pL\d])`.

Порядок проверок:

1. `title_exclude` — только по заголовку. В описаниях нормальных объявлений постоянно встречаются «зарядка», «чехол», «карта памяти», «батарея держит», поэтому проверять их там нельзя: отсеются как раз полные комплекты.
2. `description_exclude` — по заголовку и описанию. Сюда идут только признаки клонов («встроенных игр», «игр в 1»).
3. `title_include` — нужно хотя бы одно слово (по заголовку; с `include_in_description: true` — и по описанию).
4. Цена: `min_price` … `max_price` (`max_price: 0` — без верхней границы). Без цены — по `notify_without_price`.
5. Возраст: `max_age_minutes`. Время берётся из данных страницы с точностью до секунды; если его нет — из подписи «N минут назад», «сегодня в 14:30». Объявления с неизвестным временем отбрасываются, пока `notify_without_age: false`.

Общие правила задаются в `defaults`. В разделе можно переопределить любое поле; `title_exclude` и `description_exclude` раздела **добавляются** к общим, `title_include` раздела **заменяет** общий.

## Скорость и лимиты Авито

Скорость упирается не в язык, а в лимитер Авито: частые запросы получают 429/403, и объявление приходит не раньше, а позже. Поэтому интервал адаптивный — сжимается после чистых циклов и растягивается после отказов.

С `categories_per_cycle: 1` за цикл опрашивается один раздел, и при трёх разделах каждый проверяется примерно раз в три интервала. Варианты ускорить:

- поднять `categories_per_cycle` (риск 429 выше — следите за часовой сводкой в логе);
- оставить по одной ссылке на раздел;
- завести во всех разделах **одну и ту же** широкую ссылку (вся рубрика «Игровые приставки», сортировка по дате, без `q=`) и `categories_per_cycle` = числу разделов: одинаковые ссылки скачиваются один раз за цикл, а объявления раскладываются по темам белыми списками. Один запрос на все приставки сразу — но проверьте, что за интервал новых объявлений в рубрике меньше, чем помещается на первой странице.

## Файлы

| Файл | Что это |
|---|---|
| `config.json` | настройки |
| `state.json` | просмотренные объявления, номера тем, отправленные сообщения (для автоудаления) |
| `proxies.txt` | прокси, по одному в строке: `IP:порт:логин:пароль`, `socks5://IP:порт:логин:пароль`, `http://логин:пароль@IP:порт`, `IP:порт` |
| `debug_last_page.html` | последняя страница выдачи (только с `-debug`) |

`state.json` и `proxies.txt` ищутся рядом с `config.json`.

## systemd

```ini
# /etc/systemd/system/avito-watcher.service
[Unit]
Description=Avito watcher
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/opt/avito-watcher
ExecStart=/opt/avito-watcher/avito-watcher -config /opt/avito-watcher/config.json
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now avito-watcher
journalctl -u avito-watcher -f
```

## Что осталось за бортом по сравнению с Python-версией

Фильтр по рейтингу продавца и открытие карточки объявления (`fetch_details`) не перенесены: в вашем конфиге они выключены, а каждое открытие карточки — лишний запрос к Авито на каждое уведомление.
